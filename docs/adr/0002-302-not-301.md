# Resolutions answer 302, not 301

Resolution returns `302 Found` with `Cache-Control: no-store`, despite `301 Moved Permanently` being both the more semantically tempting choice and much faster for repeat visitors. A 301 is cached by the browser indefinitely, which means the second and every later visit never reaches this service — and this service supports **expiry and Deactivation**. Under a 301, a deactivated ShortLink keeps redirecting from browser caches we cannot reach, so Deactivation becomes a lie we tell the API caller; Click counts also silently collapse toward the number of distinct first-visits.

## Consequences

Every Resolution costs a round trip, which is why the read path is cache-first and why the p99 target is stated for the redirect endpoint specifically. This decision is effectively irreversible in the wrong direction: once 301s are in the wild they cannot be recalled, so switching to 301 later would strand every link issued after the switch.
